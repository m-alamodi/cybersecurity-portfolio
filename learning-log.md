# Learning Log — SOC Analyst Track

Use one entry for a meaningful study session, lab, or course milestone. Keep entries brief but specific. This log is for work actually completed; label a planned task as planned rather than completed.

## Entry Template

### [YYYY-MM-DD] — [Topic / Course Activity]

- **Learning objective:** [What did I want to understand?]
- **Key concepts:** [Concepts learned in my own words]
- **Practice performed:** [Exact exercise completed; state if theory-only]
- **Tools / data:** [Tools and sample data actually used]
- **Observations:** [What did I notice?]
- **SOC relevance:** [How could this matter for monitoring, triage, investigation, or escalation?]
- **Uncertainty / question:** [What remains unclear?]
- **Next step:** [Specific thing to review or practice]
- **Related project:** [Link, or “None yet”]

## Example of an honest entry

### [Date] — Introduction to security events

- **Learning objective:** Understand the difference between an event, an alert, and an incident.
- **Key concepts:** An event is an observable activity; an alert flags activity for review; an incident requires assessment that a security issue has occurred. The exact definitions depend on the organization’s process.
- **Practice performed:** Coursework review only; no live environment was tested.
- **Tools / data:** Course material.
- **Observations:** An alert needs context and validation; it should not automatically be described as a confirmed attack.
- **SOC relevance:** A Tier 1 analyst records evidence, investigates within scope, and escalates according to procedures.
- **Uncertainty / question:** Which fields in a sample authentication log are most useful for triage?
- **Next step:** Review a permitted sample log and document the fields.
- **Related project:** None yet.
