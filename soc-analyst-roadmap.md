# SOC Analyst Roadmap — Beginner to Job-Ready Evidence

This roadmap is intended to run alongside the Google Cybersecurity Certificate. Learn the fundamentals first; use tools only when you can explain the underlying security question. Do not claim a lab skill until you have performed and documented it.

## Phase 1 — Foundations
- Complete relevant Google coursework on security principles, risks, networks, Linux, SQL, and incident response.
- Learn core networking terms: IP addresses, ports, DNS, HTTP/S, TCP/UDP, and common log fields.
- Practice distinguishing a threat, vulnerability, security event, alert, and confirmed incident.
- Start the learning log and maintain the skills matrix.

**Evidence to publish:** a concise risk assessment or security fundamentals report based on a fictional scenario.

## Phase 2 — Log Analysis and Alert Triage
- Learn how to read timestamps, usernames, source IPs, event IDs, outcomes, and related context in logs.
- Practice asking: What triggered the alert? What evidence supports it? What benign explanation is possible? What additional telemetry is needed?
- Write a triage summary with observations, tentative classification, uncertainty, and recommended escalation.

**Evidence to publish:** a completed alert-triage report using synthetic or authorized sample data.

## Phase 3 — SIEM Practice
- Use SIEM tooling available in your course or an authorized lab. Google’s certificate includes hands-on practice with SIEM tools such as Chronicle and Splunk.
- Learn searching, filtering, time ranges, grouping, and basic correlation.
- Later, consider the official Microsoft Learn KQL path for Microsoft Sentinel if it fits the roles you are targeting.

**Evidence to publish:** explain a search/query, what question it answers, what result it returned in the lab, and its limitations. Never fabricate output.

## Phase 4 — Investigation and Reporting
- Practice creating an event timeline.
- Learn the difference between an observed fact and a hypothesis.
- Document containment or escalation recommendations without implying you changed a real production system.
- Learn to use threat frameworks such as MITRE ATT&CK as a structured reference, not as proof that an attack happened.

**Evidence to publish:** a simulated incident report and a clear escalation note.

## Phase 5 — Basic Automation
- Once you have covered the course material, use Python or SQL to help examine sample data.
- Explain input, logic, output, testing, and limitations.
- Do not upload sensitive log samples or secrets.

**Evidence to publish:** a small tested script/query and a sample output generated from safe data.

## A useful portfolio target while applying
Aim to build 2–4 clear, completed items rather than many empty folders. This is a development target, not a prerequisite for applying; apply to roles whose actual requirements you meet while building the portfolio:
1. One alert-triage report.
2. One log-analysis exercise.
3. One incident report or timeline.
4. One SIEM search or basic analysis script, when ready.

This is a suggested target, not a hiring guarantee. A portfolio helps show how you think and document work, but it does not replace required experience, work authorization, or technical competence. Do not wait for a perfect portfolio to apply to suitable roles.
